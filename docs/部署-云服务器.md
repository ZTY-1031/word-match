# 部署到云服务器（公网 IP + 8080）

## 0. 先明确形态

这套东西打包出来是**一个 jar**，页面、接口、WebSocket 全在一个进程里：

```
                    ┌─────────────────────────────────────────┐
浏览器/手机 ──HTTP──>│  公网 IP:8080                           │
            ──WS───>│  ├─ /            静态页面（Vue 构建产物）│
                    │  ├─ /api/**      REST                   │
                    │  └─ /ws/game     WebSocket              │
                    └─────────────────────────────────────────┘
```

所以**不需要 Nginx、不需要 Redis、不需要数据库**，只要：

1. 服务器上有个 JDK 17
2. 云厂商安全组放行 8080
3. 进程能常驻（systemd）

下面按顺序走一遍，全程约 10 分钟。命令以 `root` 登录为准，非 root 自行加 `sudo`。

---

## 1. 本地打包

```bash
# 前端 → 后端静态资源
cd frontend && npm run build
cd .. && rm -rf backend/src/main/resources/static && cp -r frontend/dist backend/src/main/resources/static

# 打 jar（一定要 clean，否则旧的 hash 资源会一起打进去）
cd backend && mvn -DskipTests clean package
```

产物：`backend/target/word-match-0.1.0.jar`，约 21MB。

> 本机默认 `java` 是 1.8 的话，先 `export JAVA_HOME=E:/jdk17`（Windows Git Bash 写法），否则 Maven 用 1.8 编译会失败。

---

## 2. 上传到服务器

```bash
ssh root@<你的公网IP> "mkdir -p /opt/word-match"
scp backend/target/word-match-0.1.0.jar root@<你的公网IP>:/opt/word-match/app.jar
```

统一改名为 `app.jar`，以后更新版本不用改服务配置。

---

## 3. 服务器装 JDK 17

先看有没有：

```bash
java -version
```

没装或版本低于 17：

```bash
# Ubuntu / Debian
apt update && apt install -y openjdk-17-jre-headless

# CentOS Stream / Rocky / AlmaLinux / 阿里云 Anolis 8+
dnf install -y java-17-openjdk-headless

# CentOS 7 没有 17，用 Docker 方式（见第 8 节）或手动装 Adoptium tar.gz
```

装完确认：

```bash
java -version    # 应该是 openjdk version "17.x"
which java       # 一般是 /usr/bin/java，和 systemd 配置里的路径要对得上
```

---

## 4. 先手工跑一次（排除环境问题）

```bash
cd /opt/word-match
java -jar app.jar --server.port=8080
```

另开一个终端（或 `Ctrl+C` 前先测）：

```bash
curl http://127.0.0.1:8080/api/health
# 期望：{"code":0,"data":{"store":"memory","status":"UP","rooms":0,"roundSeconds":20},"message":"ok"}
```

本机能通说明端口和包都没问题，剩下的就是“对外放行 + 常驻”。`Ctrl+C` 停掉。

---

## 5. 交给 systemd 常驻

仓库里已经准备好了 `deploy/word-match.service`：

```bash
cp /opt/word-match/word-match.service /etc/systemd/system/     # 从你上传的目录复制，或手工新建
systemctl daemon-reload
systemctl enable --now word-match
systemctl status word-match        # 应该是 active (running)
journalctl -u word-match -f        # 实时看日志，q 退出
```

服务文件内容（需要改路径时对照）：

```ini
[Service]
ExecStart=/usr/bin/java -Dfile.encoding=UTF-8 -Xms128m -Xmx256m -jar /opt/word-match/app.jar --server.port=8080
Restart=always
```

两个细节：

- `--server.port=8080` 显式写死。某些环境会塞 `SERVER_PORT` / `SERVER__PORT` 这类环境变量，Spring 会优先读它们导致端口漂移。
- **不要开多实例/多副本**。房间状态在进程内存里，起两个进程会出现“我建的房间在另一个进程里查不到”。

---

## 6. 放行 8080

两层都要开，少一层都打不开：

**① 云厂商安全组**（最常见的原因）

控制台 → 服务器 → 安全组 → 入方向 → 添加规则：

| 协议 | 端口 | 源 | 说明 |
| --- | --- | --- | --- |
| TCP | 8080 | 0.0.0.0/0 | 接词挑战 |

阿里云轻量应用服务器在「防火墙」页签；腾讯云在「防火墙/安全组」；华为云在「安全组」。

**② 服务器自身防火墙**（如果开着）

```bash
# firewalld（CentOS / Rocky 常见）
firewall-cmd --add-port=8080/tcp --permanent && firewall-cmd --reload

# ufw（Ubuntu 常见，先看状态）
ufw status
ufw allow 8080/tcp
```

## 7. 验收清单

- [ ] `curl http://127.0.0.1:8080/api/health` 返回 `code: 0`（服务器上跑）
- [ ] 浏览器打开 `http://<公网IP>:8080` 能看到首页
- [ ] 创建房间 → 拿到 6 位房间码 → 复制房间码成功
- [ ] 手机切 4G，打开同一地址，输房间码加入，双方席位都亮起来
- [ ] 打一局：两边各写一个词 → 揭晓 → 下一轮 → 撞词结算
- [ ] 刷新页面能回到当前对局（重连恢复）

> 手机走 4G 是**非同一局域网**下的真实公网链路，这一步过了才算部署成功。

## 8. 备选：Docker 部署（服务器不方便装 JDK 时）

本地 `docker build` 也行，直接在服务器上构建也行。**先把第 1 步的 jar 打好并上传整个仓库**，然后在仓库根目录：

```bash
docker build -f deploy/Dockerfile -t word-match:0.1 .
docker run -d --name word-match --restart unless-stopped -p 8080:8080 word-match:0.1
docker logs -f word-match
```

镜像基于 `eclipse-temurin:17-jre-alpine`，只跑现成的 jar，不会在服务器上装 Node/Maven。

更新版本：

```bash
docker rm -f word-match
docker build -f deploy/Dockerfile -t word-match:0.1 .
docker run -d --name word-match --restart unless-stopped -p 8080:8080 word-match:0.1
```

## 9. 可选但推荐：绑域名 + HTTPS

现在用 `http://IP:8080` 能玩，但有两个小问题：

1. **复制按钮会走降级逻辑**。`navigator.clipboard` 只在 HTTPS / localhost 下可用，代码里已经用 `execCommand` 兜住了，能用，但不是最优路径。
2. 明文传输，微信里打开链接的观感也一般。

加上域名和证书（需要域名已备案）：

```nginx
server {
    listen 80;
    server_name game.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;

        # WebSocket 必须这两行，否则握手失败、页面一直「正在连接服务端」
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 3600s;
    }
}
```

```bash
certbot --nginx -d game.example.com     # 自动签发并改写成 443
```

上了 Nginx 之后，建议把后端只绑本机：

```bash
java -jar app.jar --server.port=8080 --server.address=127.0.0.1
```

此时访问变成 `https://game.example.com`，WebSocket 自动走 `wss://`（前端是按 `location.protocol` 推导的，不用改代码），复制按钮也会走原生 clipboard。

## 10. 排查手册

| 现象 | 大概率原因 | 处理 |
| --- | --- | --- |
| 浏览器一直转圈 / 超时 | 安全组或防火墙没放行 | 第 6 节两层都检查；`curl 127.0.0.1:8080` 先排除服务问题 |
| 服务器本机能 curl，公网不行 | 只开了防火墙没开安全组（或反过来） | 两个都要开 |
| 页面能开，底部一直「正在连接服务端」 | WebSocket 被中间层拦了 | 别套 CDN/企业代理；用 IP 直连测试；上了 Nginx 要转发 `Upgrade` |
| 提交时提示「连接中断」 | 服务重启过 / 网络抖动 | 刷新页面，会自动重连并拉快照 |
| 启动报 `Port 8080 was already in use` | 旧进程还在 | `ss -lntp \| grep 8080` → `kill <pid>` |
| 启动报 `UnsupportedClassVersionError` | JDK 版本低于 17 | 装 17，或显式用 `/opt/jdk17/bin/java` |
| `scp` 覆盖 jar 报 `Text file busy` | 覆盖了正在运行的文件 | `systemctl stop word-match` 再传 |
| 服务状态 `activating` 反复重启 | 启动参数/端口有问题 | `journalctl -u word-match -n 100 --no-pager` |
| 重启服务器后房间都没了 | 内存存储，重启即丢 | 预期行为，重新建房 |
| 手机能开首页但进不去房间 | 链接里的房间码过期（房间 2 小时过期） | 重新建房 |
| 端口 8080 被公司网络封 | 出口策略 | 换端口（如 8443）并同步安全组与访问地址 |

## 11. 日常更新流程

改完代码，一条命令搞定（需要本地配好到服务器的 SSH 免密）：

```bash
bash deploy/deploy.sh root@<你的公网IP>
```

它做四件事：构建前端 → 同步静态资源到后端 → `mvn clean package` → 上传 `app.jar` 并 `systemctl restart`，最后回显健康检查结果。

手工方式等价于：

```bash
cd frontend && npm run build
cd .. && rm -rf backend/src/main/resources/static && cp -r frontend/dist backend/src/main/resources/static
cd backend && mvn -DskipTests clean package
scp target/word-match-0.1.0.jar root@<IP>:/opt/word-match/app.jar.new
ssh root@<IP> "mv /opt/word-match/app.jar.new /opt/word-match/app.jar && systemctl restart word-match"
```

> 更新会重启进程 = 正在进行的对局丢失。挑没人在玩的时候发版就行。
